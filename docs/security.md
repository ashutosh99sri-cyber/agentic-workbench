# Security model and operational limits

Trust the CLI/SDK host, installed dependency environment and OS owner. Treat project source, manifests, skills, retrieved memory and model responses as untrusted data. Configuration can reduce read/tool scope; it cannot mint host grants. Approval values identify a concrete reviewed operation and never enter model tools.

Source access rejects traversal, aliases, hard links, special files, credential/state/vendor paths and oversized content. Scan limits bound file count, bytes and directory depth. Nested Git ignore rules prune excluded parents. Known environment secrets and recognized token/private-key/assignment patterns are removed before context, result/state sinks and logs. Secret-bearing files cannot be proposed for replacement or backed up by apply. Unknown secret formats and business-sensitive data require host exclusions and context review.

Named assignment recognition includes quoted and unquoted values after `=`, `:` or Go `:=`, typed declarations and quoted subscript keys. Bare identifiers assigned to credential names can be conservatively treated as secrets; clear call/dotted references, `${VAR}` and template expansions, type names, null/bool values, compound variable names (`password: db_password`) and sentences under message names (`no_token`, `invalid_password`) are retained. Known misses include a literal that looks like a compound variable name and Go `var apiKey string = "..."` declarations. This is pattern recognition, not syntax-aware secret classification, and can produce false positives or miss unknown formats.

State is application-owned `.agentic/`, private on POSIX and protected by your user ACL on Windows. It can hold code results, diffs and original rollback content. Ignore it in Git and protect exports/backups. Its audit history is local and mutable by the OS owner; it is not a compliance attestation or authenticated multi-user service. Retention/prune is explicit and digest-bound. Active task trees, unknown intents, pending journals and live container receipts are protected. Applied backups default to 90-day retention.

The source writer is POSIX-only and uses no-follow directory descriptors, target hashes/identity, staged per-file replacements, fsync and an advisory workspace lock. Other tools that ignore that lock may still race the final check/rename; stop conflicting writers during apply. Multi-file operations can be partial after a crash. Rollback preserves later edits and ambiguous ownership instead of forcing restoration. It never stages, commits, pushes or deploys target source.

Docker requires a trusted local daemon endpoint, trusted CLI binary and already present approved image digest. Review binds their identities and snapshot/configuration/argv. Containers run UID 65534, without network/capabilities, with no-new-privileges, read-only root/source, bounded resources and only a disposable source snapshot. Client auth/proxy configuration is empty. Unique owned labels/IDs and durable receipts constrain cleanup to this runner's containers. The host daemon and kernel remain trusted; Docker is not a perfect boundary against daemon/kernel vulnerabilities. Host execution is a separate explicit weaker mode with no OS sandbox. No Windows execution/mutation is claimed.

Paid provider requests require explicit network grants and external credentials. Request/byte/token/deadline limits reduce exposure; they do not guarantee a hard monetary ceiling. Unexpected external outcomes remain unresolved until host review. No automatic telemetry, account changes, dependency install into target applications, publication or remote Git writes occur.
