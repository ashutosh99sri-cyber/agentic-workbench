# Agent capabilities and evidence

All eight role names and static/provider behaviors are listed in the README. Each returns the same validated AgentResult: schema version, task ID, role, mode, summary, evidence, findings, recommendations, proposal IDs, limitations and usage. Evidence identifies relative path, inclusive line span and original source SHA-256. Findings identify fact/inference/unknown and severity. Source is redacted before retrieval; hashes identify the original permitted file, not the redacted string.

Fact findings require at least one current source citation. Inferences and unknowns may be uncited when explicitly labeled; labels and valid citations do not prove the model's interpretation is correct. Dependency context includes bounded task IDs, findings, citations and limitations. Oversized detail is omitted with truncation indicators, so downstream agents must re-read source when they need additional evidence.

Discovery does not execute project manifests. Intelligence extracts Python classes/functions/imports/call expressions and performs cited retrieval; imported or dynamic calls remain unresolved. Architecture identifies actual dependency/module boundaries and can ask a configured provider to assess APIs, databases, security and infrastructure against source. UX statically checks explicit image alt attributes; broader provider recommendations still require browser/visual acceptance. Documentation returns a source onboarding inventory; provider mode can expand it into a guide. Engineering's static plan identifies evidence and checks; automatic candidate code generation requires a configured provider or a human-authored exact proposal. Testing does not claim a recommendation was run; Runner produces actual receipts after host approval.

The default orchestrator graph chooses UX when supported interface source is present. Analysis peers can run concurrently, with a maximum of two. Each child has its own persisted claim/result and shares the root request budget. Explicit SDK graphs are bounded, dependency-validated and cycle-free. Execution and source mutation are serialized separately and cannot become LLM tools.

Tasks pin current source inventory, contracts, effective policy/configuration and selected skills. Worker leases renew local ownership. On explicit resume, abandoned ownership older than five minutes becomes interrupted; live leases remain protected. Completed nodes are reused only after pin/role/instruction checks. Pending/unknown provider intent cannot be assumed unexecuted. Historical status output is evidence from its recorded time, not a fresh scan.

Read tools are repository_summary, read_source, search_code, lookup_memory, list_symbols and trace_symbol. They accept closed argument objects, preserve source citations, bound results and recheck source hashes. The model cannot read `.agentic`, credentials, excluded vendor/state paths or arbitrary external files. It cannot approve, apply, run tests, execute shell commands, fetch URLs or alter the graph's authority.

Each role receives the union of its selected skills' requested tools intersected with the workspace tool policy. The bundled skills request repository_summary, read_source and search_code; intelligence, engineering, testing and python-engineering also request list_symbols and trace_symbol. None grants lookup_memory automatically. A trusted custom skill can request lookup_memory within the same workspace policy. Memory lookup currently requires an exact namespace/key; persisted episodic summaries are not automatically searched or recalled across tasks. Dependency task IDs provide explicit keys for coordinated work. Cross-task recent-memory or semantic-memory discovery requires an additional host integration.
