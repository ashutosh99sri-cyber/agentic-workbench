# Recovery and retention

Use `agentic status TASK_ID --root PATH` for the saved task. `agentic resume TASK_ID --root PATH` is an explicit host action: it checks current source/configuration/skill/contract pins, marks abandoned five-minute claims interrupted, preserves completed steps and refuses unresolved provider intent across the tree. A timeout does not prove that a paid request was unexecuted. Reconcile an unknown external receipt using independent provider evidence; the framework never guesses or automatically refunds/replays it.

For a partial source operation, inspect `agentic state export --root PATH` for journal values. Keep the export private. Obtain `change_id`, then `agentic apply --rollback CHANGE_ID --root PATH` to review current eligible targets and the exact rollback digest. Repeat with `--approve DIGEST` to restore them. Any later target edit, changed policy/skill, unproved directory/stage ownership or mismatching artifact prevents unsafe cleanup or leaves a reported recovery issue. Restore or reconcile conflicts manually after reviewing evidence; never overwrite user edits to make a rollback pass.

Ordinary apply failures attempt compensation only for matching operation results. A crash may leave a partial journal. The framework does not auto-complete it, and new apply operations are blocked while source recovery remains pending. Multi-file restoration is also journaled rather than filesystem-atomic. Keep source-control backups in addition to local journals.

Docker interruption/timeout/overflow cleans the exact owned container and records the outcome. If the daemon is unavailable, its receipt remains cleanup_required. From trusted SDK host code, `wb.cleanup_tests()` verifies current executable/endpoint/labels and removes only eligible pending owned containers. Do not remove unrelated Docker containers. This cleanup API is separate from model tools.

`agentic state prune --root PATH --days 30` returns exact eligible task/record/memory IDs plus a digest. Repeat with its approval to prune only those application-owned records. New history invalidates the review. Active tasks, pending recovery, unknown intents and uncleared containers are retained; applied rollback backups have a separate default 90-day retention. Expired backups make rollback unavailable, accurately reported. Pruning never deletes application source.
