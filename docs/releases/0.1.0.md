# Agentic Workbench 0.1.0

Status: the GitHub developer preview was published on 17 October 2026. PyPI and npm
uploads remain pending verified publisher access and npm namespace ownership. Do not
treat the commands below as evidence of registry publication.

## Installation

After the registry versions are verified:

```sh
python3 -m venv .venv-agentic
.venv-agentic/bin/python -m pip install "agentic-workbench==0.1.0"
.venv-agentic/bin/agentic --version
npm install --ignore-scripts @agentic-workbench/node@0.1.0
```

For optional OpenAI use, install `agentic-workbench[openai]==0.1.0` instead. Supply
credentials from a host secret manager or `--prompt-key`; never place keys in source,
arguments, project configuration or chat. The Node adapter wraps the installed
Python CLI, so configure its absolute executable when it is not on PATH.

Locally downloaded artifacts can be installed independently of registry access:
`python -m pip install /absolute/path/to/agentic_workbench-0.1.0-py3-none-any.whl`
and `npm install --ignore-scripts /absolute/path/to/agentic-workbench-node-0.1.0.tgz`.
Verify their SHA-256 values against the supplied release checksums first.

## Included

- Python CLI/SDK, eight role agents, ten original skills, Python/source facts,
  lexical and validated embedding retrieval, source-selection/impact context.
- Persistent bounded orchestration, typed tools/providers, durable effect receipts,
  cancellation, resumable approvals and verified Python repair.
- Explicit POSIX changes, separate test execution approval, source/digest checks,
  approved pinned-image Docker or explicit trusted-host execution, rollback.
- Node subprocess integration, optional TypeScript structural analysis and read/review
  MCP integration. No automatic dependency installation or provider calls.

This packages the reviewed public runtime; release preparation changes package
metadata, tests, release verification and documentation, without changing runtime
security or approval behavior. Detailed changes are in [the changelog](../../CHANGELOG.md).

## Compatibility and limitations

Python 3.11–3.14 and Node 24+. Guarded changes and Runner execution require POSIX;
Windows support is limited to [read-only operations](../support-matrix.md). Docker
requires a trusted daemon and an explicitly provisioned digest-pinned image.
The default provider is none. Static and mocked-provider checks do not establish
live model quality, inference cost, arbitrary heavy-task success or production
service operation. The Node package has no runtime npm dependencies but requires
an installed Python runtime. Public APIs remain pre-1.0 and consumers should pin versions.

## Release verification and publication

The manual release-verification workflow resolves the immutable version tag, runs
all reusable CI jobs, builds that same clean source, checks wheel and sdist consumers,
tests the packed npm archive against the installed CLI, and records source/test/artifact
hashes. It has read-only repository permission and no publication credentials.
Registry upload is a separate authorized action using those exact verified files.

Before first upload, the owner must authenticate to PyPI and npm and establish the
npm `agentic-workbench` scope. A registry 404 is not an ownership guarantee. No
passwords, persistent registry tokens or recovery codes are stored by this release.
PyPI [trusted publishing](https://docs.pypi.org/trusted-publishers/) and npm
[trusted publishing](https://docs.npmjs.com/trusted-publishers/) support short-lived
workflow credentials after the owner configures the registry-side trust relationship;
that trust is not configured by the existing verification-only workflow.

Use a new version for corrections; never replace a tag or an uploaded artifact.
If a security issue requires withdrawal, follow the registry's yank/deprecation
procedure and publish a reviewed correction. Sensitive reports go through
[GitHub private reporting](https://github.com/ashutosh99sri-cyber/agentic-workbench/security/advisories/new).

## Registry publisher controls

The separate `publish-pypi-010.yml` workflow is manually dispatched from protected
`main`, uses the `pypi` environment, and obtains short-lived PyPI credentials through
OIDC. It downloads only the reviewed 0.1.0 wheel, verifies its fixed SHA-256, and
fails before publication if the bytes differ. It does not rebuild the package,
upload a source archive, accept a user-supplied URL/version, or use a stored API key.
The original verification workflow retains its read-only permissions. The registry
owner must configure the exact repository, workflow and environment as a PyPI
pending publisher before the first upload. New package versions need a reviewed
publication configuration; existing tags and distribution bytes must not be replaced.
