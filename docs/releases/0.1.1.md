## Process cleanup correction

Darwin can return `EPERM` when signaling a process group containing only unreaped
exited processes. A local native probe observed `EPERM` before reaping and `ESRCH`
after reaping in all 12 cases. This is consistent with
[Apple's XNU group-signal implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c):
group iteration excludes zombie processes and the POSIX request reports `EPERM`
when no eligible member is found. The exact intermittent hosted scheduling window
was not reproduced by the initial 300-run stress baseline.

The shared helper now waits at most five seconds for the owned parent after
`EPERM`, then retries `SIGKILL` against the group. A missing group is accepted;
persistent denial or a live-parent timeout remains `EXECUTION_ERROR`. An exited
parent alone no longer justifies ignoring a denied group signal. Unconditional
cleanup remains in `finally`; the redundant earlier Runner signal was removed.
The TypeScript capture path already uses this helper, and stdio MCP now reuses it.

The regression tests failed against the old helper for the exit race and for a
persistent denied group after parent exit. They also retain the live-parent timeout
negative case. The permission-recovery wait can add up to five seconds before an
explicit cleanup failure; trusted-host execution remains without an OS sandbox.

.venv-agentic/bin/python -m pip install /absolute/path/to/agentic_workbench-0.1.1-py3-none-any.whl
.venv-agentic/bin/agentic --version
